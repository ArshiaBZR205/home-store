## ۸. Retrospective

### Start (شروع کنیم)
- نوشتن تست از ابتدا (TDD)
- جلسهٔ Daily منظم
- استفاده از GitHub Issues

### Stop (متوقف کنیم)
- کد زدن بدون تست
- Commitهای بزرگ
- کار انفرادی

### Continue (ادامه دهیم)
- Code Review
- مستندسازی
- استفاده از AI با شفافیت

---

## ۹. درس‌های آموخته‌شده

1. **نیازمندی‌ها را دقیق‌تر بنویسیم** — بعضی User Storyها مبهم بودند.
2. **تست را جدی بگیریم** — بدون تست، تغییرات خطرناک است.
3. **زمان‌بندی واقع‌بینانه** — ۱۰ Story برای ۵ هفته زیاد بود.
4. **از AI درست استفاده کنیم** — برای مستندات عالی، برای کد باید بازبینی 
شود.
5. **ارتباط تیمی مهم است** — Daily کمک کرد.
